# Short Onboarding and Personalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new user answers three questions, gets a safe starter workout, and is offered the rest of
the profile (equipment, experience and movement, conditions) after finishing it.

**Architecture:** Basic setup saves a starter profile with `onboardingCompleted = true` and a new
`personalizationCompleted = false`. Every existing `onboardingCompleted` gate is untouched. A new
`PERSONALIZE` route takes over the Equipment, Movement and Conditions steps from onboarding and sets the
flag. Prompts on the workout summary, Today and Profile read the flag.

**Tech Stack:** Kotlin, Jetpack Compose (Material 3), Room, Navigation Compose, JUnit 4 + Truth, Compose UI tests.

**Spec:** `docs/superpowers/specs/2026-11-21-short-onboarding-design.md`. Welcome v2 (`docs/welcome-screens-v2.md`) is a separate PR and is not part of this plan.

**Deviation from spec §2 "Shared code":** once basic setup stops asking for equipment, movement and
conditions, onboarding no longer uses that draft and validation logic. It **moves** to
`feature/personalize/` instead of being extracted into a shared unit. Nothing is duplicated.

## Global Constraints

- Branch from `main`. The PR targets `main` and is not stacked.
- Room schema goes from 19 to 20. `WALLCRAWL_SCHEMA_VERSION = 20`. Commit `app/schemas/.../20.json`.
- Archive format goes from 10 to 11. `ARCHIVE_VERSION = 11`. Archives below 11 restore `personalizationCompleted = true`.
- Existing profiles migrate to `personalizationCompleted = true` (`NOT NULL DEFAULT 1`).
- Starter profile: `experienceLevel = BEGINNER`, `availableEquipment = [BODYWEIGHT]`, `trainingConstraints = {LOW_IMPACT_ONLY}`, `movementCapabilities = MovementCapabilities.unknown()`, no conditions, `name` and `gender` model defaults.
- Units: `LBS` when the device region is `US`, `LR` or `MM`, otherwise `KG`.
- Basic setup defaults: days 3 (chips 2–6), minutes 30 (chips 20/30/45/60). The goal is required, single choice.
- Today card dismissal: 7 days, stored in SharedPreferences file `"personalize_prompt"`, key `"dismissed_at"`. It is not exported, restored or cleared.
- Every new string exists in `values/` and `values-es/` (`StringResourceParityTest` enforces this). Follow `docs/localization.md`.
- Build commands need `JAVA_HOME=/opt/homebrew/opt/openjdk@17 ANDROID_HOME="$HOME/Library/Android/sdk"`. Instrumented runs use a pinned `ANDROID_SERIAL`, and the final run is at 320×640 dp.

## Review Focus

1. **Process death in the middle of personalization:** the draft and the current step survive through `SavedStateHandle`, like onboarding does today. Test in Task 3.
2. **System Back inside personalization:** Back on step 2 or 3 goes to the previous step and saves nothing. Back on step 1 leaves without saving. Test in Task 3.
3. **Device region empty or unknown** (`Locale("en")`, country `""`): units fall back to `KG`. Test in Task 4.
4. **A backup made in the starter state** (flag false) round-trips with false, so the prompts come back after restore. Test in Task 2.
5. **Basic setup at 320×640 dp and 200% font:** the goal tiles wrap, the button stays reachable, nothing clips. Test in Task 7.
